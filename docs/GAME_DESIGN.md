# 행성 지키기 — 게임 디자인 문서 v0.1

> 상태: 프로토타입(M0) 구현 완료 · 수치는 `src/config.ts` 와 동기화

## 1. 한 줄 요약

행성이 쉬지 않고 찍어내는 수백 개의 병력을 **드래그로 원하는 만큼 떼어내 직접 움직이고**,
적 행성에 **뭉쳐서 돌파할지 / 둘러싸서 수비대부터 깎을지**를 버튼이 아니라 **병력의 위치로** 결정하는 실시간 행성 점령 디펜스.

## 2. 디자인 기둥 (Pillars)

| # | 기둥 | 의미 | 구현에서 지키는 방법 |
|---|------|------|----------------------|
| 1 | **위치가 곧 명령** | '교전 모드 / 점령 모드' 같은 스위치가 없다. 병력이 어디에 있느냐가 무엇을 공격하는지 정한다. | 대기권 안 = 행성 공격, 밖 = 병력 교전 (§4.3) |
| 2 | **원하는 만큼 정확하게** | 몇 기를 어디로 보낼지 플레이어가 고른다. | 드래그 선택, 행성 단위 선택, 절반 선택, 부대 지정 (§6) |
| 3 | **한눈에 읽히는 전장** | 점 하나 = 병사 하나, 색 = 진영. 숫자보다 그림으로 판단. | 대기권 점선, 방어도 링, 고립 병력 깜빡임 (§7) |

## 4. 핵심 규칙

### 4.1 행성

| 크기 | 반경 | 생산(기/초) | 궤도 정원 | 최대 방어도 | 중립 수비대 |
|------|-----:|------------:|----------:|------------:|------------:|
| 소형 | 18 | 0.5 | 30 | 80 | 6 |
| 중형 | 26 | 0.8 | 50 | 150 | 12 |
| 대형 | 34 | 1.1 | 80 | 240 | 20 |

- 소유 상태: 아군 / 적 / 중립. 중립 행성은 **생산하지 않고** 수비대만 있다.
- **생산**: 소유 행성은 초당 정해진 수만큼 병력을 만든다. 그 행성 **궤도를 도는 병력**이 정원에 차면 생산이 멈춘다.
  → 병력을 밖으로 내보내야 생산이 계속된다. 쌓아두기만 하면 손해.
- **대기권**: 행성 표면에서 24 바깥까지. 화면에 점선 원으로 표시된다.
- **방어도**: 적의 강하 공격으로 깎인다. 2초간 공격받지 않으면 초당 최대치의 4% 씩 회복.

### 4.2 병력 (MVP 는 한 종류)

| 체력 | 공격력 | 공격 간격 | 사거리 | 속도 | 행성 피해 배율 |
|-----:|-------:|----------:|-------:|-----:|---------------:|
| 4 | 1 | 1.0초(±15%) | 24 | 55 | 0.6 |

- 상태: **궤도 대기**(행성을 돈다) / **이동** / **위치 고수**(우주 공간에 멈춤) / **고립**(아래 4.5)
- 사격은 **자동**이다. 플레이어는 '누구를 쏠지'가 아니라 '어디에 둘지'를 정한다.
- 이동 중에도 사격한다(멈춰서 싸우지 않는다).

### 4.3 위치 규칙 — 이 게임의 핵심

```
            ·  ·  ·  ·  ·            ← 대기권 경계 (점선)
         ·                 ·
       ·    ○ ○  수비대  ○   ·        대기권 안의 적 병력  → 행성 방어도를 직접 공격 (강하)
      ·   ○   ( 행성 )    ○   ·       대기권 밖의 병력      → 사거리 안의 적 병력과 교전
       ·    ○    ○    ○     ·
         ·                 ·
            ·  ·  ·  ·  ·
   ▶▶▶ 돌파: 안으로 뭉쳐 들어간다          ◎ 포위: 경계 바로 밖에 둘러선다
```

1. **적(또는 중립) 행성 대기권 안**에 있는 병력은 행성 표면(방어도)을 쏜다. 적 병력은 무시한다.
2. **그 밖의 모든 곳**에서는 사거리 안의 가장 가까운 적 병력을 쏜다.
3. **방어막은 궤도 수비대가 유지한다.** 강하 공격 1발의 행성 피해 =
   `공격력 × 0.6 × 공격측 수 / (공격측 수 + 수비측 수)` (둘 다 그 대기권 안의 병력 수)
   → 수비대가 두꺼우면 돌파의 효율이 떨어진다. 압도적인 수로 밀거나, 수비대를 먼저 줄여야 한다.
4. 방어도가 0 이 되면 **대기권 안에 병력이 가장 많은 진영**이 행성을 차지한다. 방어도는 최대치의 40% 로 시작.
5. 이동 명령은 목적지가 아닌 적 행성의 대기권을 **자동으로 돌아간다** (의도치 않은 강하 방지).
   반대로 목적지가 대기권 안이면(돌파, 또는 선을 행성 위로 그은 경우) 그대로 들어간다.

### 4.4 두 가지 기본 전술 (그리고 그 사이의 모든 것)

| | 돌파 (집중 대형 → 적 행성) | 포위 (산개 대형 → 적 행성) |
|---|---|---|
| 동작 | 진입 방향으로 뭉쳐 대기권 안으로 들어가 궤도를 돌며 방어도를 친다 | 대기권 바로 밖에 원호로 넓게 둘러서서 궤도 수비대를 사거리에 넣는다 |
| 장점 | 빠르다. 점령 순간 적 생산이 멈추고 수비대가 **고립**된다 | 손실이 적다. 넓게 서므로 동시에 사격하는 아군 수가 많다 |
| 단점 | 들어가는 동안 수비대에게 일방적으로 맞는다(강하 중엔 병력을 안 쏜다). 점령 후 고립된 잔당이 행성을 되찾으려 한다 | 느리다. 그동안 적 행성은 계속 생산하고, 다른 곳에서 증원이 온다 |
| 언제 | 수비대가 얇거나, 내 병력이 압도적일 때 | 수비대가 두꺼울 때 → 깎은 뒤 돌파로 마무리 |

이 두 가지는 **버튼이 아니라 결과**다. 플레이어는 일부만 떼어 반대편에서 돌파시키고 나머지로 포위하거나,
우클릭 드래그로 행성 앞에 횡대를 그어 수비대를 끌어내는 등 원하는 대로 섞을 수 있다.

**밸런스 검증** (헤드리스 시뮬레이션, 중형 행성 · 공격측 증원 없음 · 수비측 생산 0.8/s):

| 공격 vs 수비 | 돌파만 | 포위 → 수비대가 줄면 돌파 | 해석 |
|---|---|---|---|
| 60 vs 10 | 7.0초 점령, 5기 손실 | 8.1초 점령, 2기 손실 | 수비가 얇으면 둘 다 OK, 돌파가 빠름 |
| 60 vs 30 | 10.0초 점령, 11기 손실 | 18.8초 점령, 13기 손실 | 돌파 우세 (생산을 빨리 끊는 이득) |
| 100 vs 40 | 6.2초 점령, 31기 손실 | 8.4초 점령, 17기 손실 | 포위가 손실 절반 |
| 100 vs 70 | 12.7초에 점령했으나 **고립 잔당이 탈환** | 15.4초 점령, 40기 손실 | 수비가 두꺼우면 돌파는 역효과 |
| 60 vs 50 | 실패 | 실패 | 병력 우위가 부족하면 어떤 전술로도 안 된다 |

> 초기 버전은 방어도가 낮아 '돌파'가 모든 경우를 지배했다 (1초 만에 점령, 수비대 고립으로 전투 자체가 끝남).
> 궤도 장악률 공식(3번 규칙)과 방어도 상향으로 지금의 균형을 만들었다. 수치는 계속 조정 대상.

### 4.5 고립 (보급 단절)

- 행성이 점령되는 순간, 그 행성 **궤도를 지키던** 이전 소유자의 병력은 **고립**된다.
- 고립 병력: 초당 체력 −0.4 (약 10초 뒤 소멸), 공격력 ×0.5. 화면에서 깜빡인다.
- **아군 행성 대기권에 들어가면** 고립이 풀린다. (귀환 버튼 = 가장 가까운 아군 행성으로)
- 고립 병력은 여전히 (이제 적의 것이 된) 행성 대기권 안에 있으므로 **자동으로 행성을 되치려 한다.**
  점령 직후 방어도가 40% 밖에 없어서, 잔당이 많으면 실제로 되찾기도 한다 → 돌파 후엔 잔당 정리가 필요.
- 행성을 **모두 잃은 진영**의 병력은 전원 고립된다 (버티기 방지).

### 4.6 승패

- **정복전(현재 구현)**: 모든 적 진영의 행성과 병력을 없애면 승리. 내 행성과 병력이 모두 사라지면 패배.
- **방어전(예정, §11)**: 모성을 N 웨이브 동안 지킨다.

## 5. 한 판의 흐름

| 구간 | 시간 | 플레이어가 하는 일 |
|------|------|--------------------|
| 초반 | 0~1분 | 모성(대형) 하나 + 12기. 가까운 소형 중립 행성을 포위→돌파로 먹는다. 생산 행성 수 = 경제력 |
| 중반 | 1~4분 | 중립 확장 경쟁, 적과 첫 충돌. 맵 중앙의 대형 중립(수비대 30)이 요충지 |
| 후반 | 4~8분 | 병력 수백. 여러 전선 동시 운용, 적 모성 돌파, 고립 잔당 처리 |

## 6. 조작

| 동작 | PC | 모바일 |
|------|----|--------|
| 범위 선택 | 좌클릭 드래그 (Shift: 추가) | 한 손가락 드래그 |
| 행성 병력 선택 | 아군 행성 클릭 | 탭(선택이 없을 때) / 길게 누르기 |
| 주변 전부 선택 | 더블클릭 | 더블탭 |
| 이동 · 공격 | 우클릭 | 탭(선택이 있을 때) |
| 횡대 배치 | 우클릭 드래그로 선 긋기 | 대형 '산개' 후 탭 (진행 방향에 수직 횡대) |
| 대형 전환 (집중/산개) | F | 하단 버튼 |
| 전체 선택 / 절반 / 해제 | A / Q / Esc | 하단 버튼 |
| 전체 공격 | G → 목표 클릭 | 버튼 → 목표 탭 |
| 귀환 | R | 하단 버튼 |
| 부대 지정 | Ctrl+1~9 지정, 1~9 호출 | (예정: 부대 버튼) |
| 카메라 | 휠 확대, 가운데 드래그, 방향키, H 전체 보기 | 두 손가락 이동/핀치 확대 |
| 일시정지 / 배속 | P·Space / Tab | 상단 버튼 |

- 마우스를 올리면 커서 옆에 **지금 명령하면 일어날 일**이 표시된다 (`합류 / 돌파 ▶ / 포위 ◎ / 이동 / 횡대 이동` + 선택 수).
- 같은 '지점 지정'이 대상에 따라 다르게 해석된다:
  - 아군 행성 → 궤도 합류(증원)
  - 적·중립 행성 + 집중 → 돌파 / + 산개 → 포위
  - 빈 우주 + 집중 → 원형 밀집 / + 산개 → 진행 방향에 수직인 횡대
- '원하는 수만큼': 행성 궤도의 병력 일부만 드래그로 긁거나, 행성을 선택한 뒤 '절반'을 눌러 반씩 떼어낸다.

- 행성: 중앙 숫자 = 소유자의 궤도 병력 수(정원이 차면 노란색), 둘레 링 = 방어도, 점선 = 대기권.
- 공격받는 행성은 대기권이 공격자 색으로 번쩍인다. 모성은 안쪽 링으로 구분.
- 마우스를 올린 행성은 툴팁으로 크기·소유·방어도·생산·정원을 보여준다.
- **세로 화면에서 시작하면 맵 자체를 세로로 길게 생성**한다(같은 시드, 가로세로만 교환). 휴대폰 세로 플레이 대응.
- 휴대폰 가로 화면에서는 명령 바가 오른쪽 세로 줄로 바뀌어 세로 공간을 확보한다.

## 8. AI

규칙 기반. 플레이어와 **똑같이 명령(Command)만으로** 게임에 개입한다 (치트 없음).

1. **방어**: 자기 행성 근처 적 병력 × 1.3 이 궤도 병력보다 많으면, 가까운 행성의 여유 병력을 증원으로 보낸다.
2. **공격 대상 선정**: `가치(생산량, 적 모성 가산) / 필요 전력(주변 수비대 × 1.4 + 방어도/6) / 거리` 점수 상위 3개 중 병력이 되는 곳.
3. **전술**: 수비대가 8기 이상이고 투입 병력의 30% 를 넘으면 **포위 → (수비대가 충분히 줄거나 30초 경과) → 돌파**. 아니면 바로 돌파.
4. **철수**: 포위 중 수비대보다 수가 밀리거나, 돌파 병력이 25% 이하로 줄면 귀환.
5. 고립 병력은 행성을 되찾을 가능성이 있으면 버티고, 아니면 귀환.

| 난이도 | 판단 주기 | 공격 전력 배율 | 포위→돌파 전술 | 예비 병력 |
|--------|----------:|---------------:|:--------------:|----------:|
| 쉬움 | 3.0초 | ×2.0 | ✗ | 정원의 30% |
| 보통 | 1.5초 | ×1.5 | ✓ | 20% |
| 어려움 | 0.8초 | ×1.25 | ✓ | 12% |

## 9. 맵

- 시드 기반 **회전 대칭** 생성: 한 진영 몫(부채꼴)에 행성을 배치하고 진영 수만큼 회전 복제. 2인은 완전 점대칭.
- 각 모성 근처에 소형 중립 1~2개를 보장(초반 선택지), 중앙에 수비대 30의 대형 중립(요충지).
- 크기: 2인 1500×940, 3인 1700×1100, 4인 1800×1160 (세로 화면이면 가로세로 교환).

## 10. 기술 설계

### 10.1 플랫폼 전략: 웹 기술 하나로 PC + 모바일

PC/모바일이 미정이고 결국 둘 다 할 계획이므로, **TypeScript + HTML5 Canvas** 한 코드베이스로 간다.

| 배포 대상 | 방법 |
|-----------|------|
| 브라우저(PC/모바일) | 정적 사이트 (`npm run build` → `dist/`). GitHub Pages 등 |
| PC 앱 / Steam | Tauri(가벼움) 또는 Electron 으로 `dist/` 래핑 |
| iOS / Android | Capacitor 로 `dist/` 래핑 → 스토어 배포 |

- 입력은 **Pointer Events** 로 마우스/터치/펜을 한 경로에서 처리하고, 장치별로 해석만 다르게 한다.
- `vite.config.ts` 에서 `base: './'` (상대 경로) → 어떤 래퍼에서도 그대로 동작.
- **대안**: 유닛이 수만 개로 늘거나 3D 연출이 필요해지면 Godot/Unity 를 검토. 그때를 대비해 시뮬레이션을 렌더러와 완전히 분리해 두었다
  (`src/sim/` 은 DOM 을 전혀 모른다 → 로직 이식이 쉽다).

### 10.2 구조

```
src/
  config.ts          밸런스 수치 전부
  sim/               ── 순수 게임 로직 (DOM 없음, 헤드리스 실행 가능)
    world.ts         고정 타임스텝(30Hz) 시뮬레이션: 이동 → 집계 → 전투 → 사망 → 점령 → 생산
    orders.ts        명령 → 유닛별 목표 지점(대형 슬롯) 배정
    ai.ts            규칙 기반 AI (명령만 사용)
    mapgen.ts        시드 기반 대칭 맵 생성
    spatial.ts       공간 해시 (근접 탐색)
    rng.ts           결정론적 난수
    match.ts         월드 + AI 묶음
  render/            Canvas 렌더러, 카메라
  input/             마우스 · 터치 · 키보드 → Game 메서드
  ui/                DOM HUD
  game.ts            루프, 선택 상태, 명령 발행
tests/               vitest: 규칙 · 대형 · 맵 · 결정론 · AI 대전
```

- **결정론**: 시뮬레이션 안에서는 시드 난수만 쓰고, 명령은 다음 틱 시작에 적용된다.
  같은 시드 + 같은 명령 = 같은 결과 (테스트로 보장) → **리플레이**, **락스텝 멀티플레이**의 기반.
- **성능**: 유닛 800기 기준 틱당 ~0.4ms (헤드리스). 렌더는 진영별로 경로를 묶어 한 번에 그린다.
