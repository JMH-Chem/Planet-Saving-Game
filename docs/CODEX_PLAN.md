# Codex 개선안과 다음 개발 순서

작성: 2026-10-29. 기존 [게임 디자인 문서](GAME_DESIGN.md)의 규칙과 로드맵을 유지하면서, 이번 수정과 다음 작업의 완료 기준을 정리한다.

## 이번에 구현한 것

| 항목 | 결과 | 확인 방법 |
|---|---|---|
| 다자전 플레이어 탈락 | 플레이어가 전멸하면 즉시 경기 진행을 멈추고 패배 화면 표시. 남은 AI 중 임의의 승자를 만들지 않음 | 적 2·3명 생존 사례, 브라우저 결과 화면 |
| 관전 | 자동 관전에서는 1번 진영이 탈락해도 최종 승자를 정할 때까지 계속 진행 | 별도 회귀 테스트 |
| 점령 판정 | 사망자를 제거한 뒤 생존 병력으로 점령권 판정. 공격군이 모두 죽었으면 소유권 유지 | 전멸한 다수와 생존한 소수의 경쟁, 전원 전멸 사례 |
| 맵 경계 | 집중 대형과 짧은 횡대 명령의 대형 전체를 맵 안쪽으로 이동 | 네 모서리, 짧은 선, 실제 도착·병력 중첩 검사 |
| 디자인 비교 | 기본은 기존 디자인. `?design=codex`로 새 버전 선택. 모드·난이도·시드를 유지하며 메뉴에서 전환 | 원본·Codex, PC·모바일의 실제 입력 검사 |

`World.winner`는 세계의 최종 승자다. `Match.finished`는 플레이어가 진행하는 판의 종료 여부도 포함한다. 이 구분을 유지해야 관전·밸런스 측정을 망가뜨리지 않고 플레이어 패배를 처리할 수 있다.

## 1. 첫 판의 이해와 안정화

다음 작업은 짧은 튜토리얼 3개다. 생산과 선택 → 빈 행성 돌파 → 두꺼운 수비대 포위 후 돌파 순으로, 설명을 읽는 대신 명령을 직접 내리게 한다. 재시도할 때 같은 배치를 제공하고, 자유 전투로 바로 넘어갈 수 있게 한다.

완료 기준:

- PC와 터치에서 각각 선택·목표 지정·취소를 끝까지 수행할 수 있다.
- 각 튜토리얼은 목표 행동으로만 완료되며, 잘못된 행동 뒤에도 재시도할 수 있다.
- 메뉴 → 플레이 → 도움말 → 복귀 → 패배 → 재시작을 브라우저 회귀 검사에 포함한다.
- 다수 시드에서 병력 좌표·소유권·생존 수의 불변 조건을 검사한다. 화면 비율 변경과 다자전도 포함한다.
- 실제 중급 휴대폰에서 큰 전투를 측정한다. 프레임 시간·시뮬레이션 시간·메모리를 따로 기록한 뒤 필요한 부분을 최적화한다. 헤드리스 브라우저 결과를 실기기 성능으로 간주하지 않는다.

## 2. 명령 기록과 리플레이 기반

현재의 결정론적 `sim/` 구조를 활용한다. 먼저 버전이 있는 기록 형식을 만들고, 그 다음 재생 UI를 붙인다.

- 기록: 규칙 버전, 밸런스 버전, 시드, 모드, 난이도, AI 수, 가로·세로 맵 설정, 틱 번호와 같은 틱 안의 명령 순서.
- 플레이어 입력은 화면 좌표가 아닌 확정된 `Command`로 기록한다. 렌더링 시간·오디오 난수는 기록에 섞지 않는다.
- 재생은 같은 시뮬레이션을 사용한다. 유닛 위치·체력·진영·행성 방어도·통계·종료 상태를 포함한 상태 해시로 일치 여부를 검사한다.
- 저장·재개를 추가할 때는 난수 상태, 다음 유닛 ID, 대기 명령, AI 작전, 웨이브 진행 상태도 직렬화한다. `World`만 복사하면 같은 판이 복원되지 않는다.
- 버전이 달라 재현할 수 없는 기록은 조용히 재생하지 말고 호환 여부를 알려 준다.

완료 기준: 같은 기록을 두 번 재생했을 때 주요 체크포인트와 최종 상태가 일치하고, 일시정지·배속·화면 크기가 결과를 바꾸지 않는다.

## 3. 이 게임의 개성을 보여 주는 전술 실험실

작은 전투 하나에서 같은 시작 병력을 놓고 **돌파 / 포위 후 돌파**를 비교한다. 먼저 전용 실험 스테이지로 범위를 제한하고, 이후 리플레이의 특정 시점에서 갈라지는 기능으로 확장한다.

화면에는 점령까지 걸린 시간, 아군 손실, 남은 수비대, 점령 성공 여부를 보여 준다. 실패한 실험도 남겨서 왜 실패했는지 되돌아볼 수 있게 한다. 포위에서 돌파로 바꾸는 시점은 사용자가 조절한다.

주의할 설계 결정:

- 분기 이후 AI는 새 상황에 맞춰 다시 판단해야 한다. 이전 판의 AI 명령을 그대로 틀면 공정한 비교가 되지 않는다.
- 단순한 병력 수 비율을 실제 승률처럼 표시하지 않는다. 같은 규칙으로 실행한 시뮬레이션 결과를 제시한다.
- 먼저 완료할 것은 단일 전투 비교다. 현재 변경에는 리플레이·실험실이 구현되어 있지 않다.

완료 기준: 같은 초기 조건으로 두 전술을 실행·초기화할 수 있고, 결과를 수치와 재생으로 확인할 수 있다.

## 4. 깊이는 한 번에 한 축씩 추가

튜토리얼과 전술 비교를 플레이해 본 뒤, 행성 특성 하나부터 시험한다. 생산 특화와 방어 특화 정도로 선택의 의미를 검증하고, 기존 단일 유닛 규칙을 유지한 상태에서 재미가 늘어나는지 본다. 여러 유닛·업그레이드·멀티플레이를 동시에 도입하면 밸런스와 UI 원인을 분리하기 어렵다.

완료 기준: 새 특성을 보고 플레이어가 다른 이동·공격 결정을 내릴 수 있고, 기본 정복전·방어전의 자동 검사를 계속 통과한다.

## 디자인 비교와 협업 경계

실행 방법과 화면은 [디자인 비교 문서](DESIGN_COMPARISON.md)에 있다. 기본 디자인을 바꿀지는 실제 플레이 비교 후 결정한다.

- 기존 `index.html`, `src/style.css`, Canvas 그림은 보존했다. 비교 선택기만 메뉴에 덧붙인다.
- Codex 전용 레이아웃과 스타일은 `src/design/`에 모았다. 외부 폰트·이미지·런타임 의존성은 추가하지 않았다.
- 시뮬레이션·입력·HUD 이벤트는 공유한다. 디자인마다 별도의 게임 로직을 만들지 않는다.
- Claude와 동시에 작업할 때 `src/main.ts`·공통 HUD처럼 겹치는 파일의 변경 의도를 먼저 확인하고, 디자인 실험은 해당 폴더 안에서 진행한다. 테스트가 통과하는 단위로 통합한다.

검증 명령:

```bash
npm test -- --maxWorkers=1 --testTimeout=30000
npm run build:single
npm run test:browser
```

브라우저 검사는 설치된 Chromium을 사용한다. 실행 파일 이름이 다르면 `CHROMIUM_PATH`로 지정한다. 새 의존성이나 브라우저를 자동 다운로드하지 않는다.
